Active Defender SOC AI

A dual-engine threat analysis system powered by Machine Learning + LLaMA 3.
Designed to drastically reduce false positives and automate SOC tier-1 response.

⚙️ How It Works

Every alert goes through a two-stage process. Think of it like a fast security guard at the door, and a senior detective inside.

Engine 1 — Speed

🟢 Machine Learning Filter

Analyzes the alert text, time of day, and attack frequency using a trained Random Forest model.

  • Response time: ~0.1 seconds
  • Only triggers if confidence ≥ 90%
  • Drops known false positives instantly
Engine 2 — Intelligence

🔵 LLaMA 3 Brain

Deep forensic analysis combining the alert, IP history, Threat Intel, and SOC playbooks.

  • Response time: ~60–120 seconds
  • Always handles Threat Intel-flagged IPs
  • Makes contextual, explained decisions

🏷️ Alert Classifications

The AI always assigns one of four labels:

LabelMeaningAuto-Action?Example
Critique Confirmed active attack. Immediate response required. Yes SQL Injection, Ransomware, Malware
Suspect Abnormal activity, not yet confirmed dangerous. No Port scan (no threat intel)
Informatif Normal event, no risk. For logging only. No Routine system event
Faux positif Looks like a threat but is completely legitimate. No Successful employee login
Auto-Action Safety Rule Automated actions only execute when: classification = Critique AND AI confidence ≥ 85%. A human override is always possible.

Automated Action Types

ActionWhenEffect
firewall-drop External IP (not 192.168.x / 10.x / 172.x) Blocks the IP at the perimeter firewall
wazuh-isolate-endpoint Internal IP (192.168.x / 10.x / 172.x) Quarantines the machine without blocking the whole network

🌐 Network Setup (Tailscale)

Both machines must be on the same Tailscale network. Once they are, use the AI machine's Tailscale IP.

1

Find the AI's Tailscale IP

On the AI machine, open a terminal and type:

tailscale ip -4

This gives you an IP like 100.64.X.X. That is the address the Blue Team will use.

2

Start the AI API server

On the AI machine, navigate to the project folder and run:

uvicorn api:app --host 0.0.0.0 --port 8000
3

Verify connection from Blue Team machine

Open a browser and go to: http://100.64.X.X:8000/health
You should see: {"api": "ok", "engine1_ml": "ok", ...}

🎛️ ML Engine Toggle

You can enable or disable Engine 1 at any time. This is useful for testing or comparing results.

Option A — In the stress test script

Open stress_test.py and change line 14:

python — stress_test.py, line ~14
USE_ML_ENGINE = True   # Change to False to bypass ML entirely

Option B — Via the API URL (no restart needed)

Add ?disable_ml=true to the end of the API URL in your n8n node:

url
http://100.64.X.X:8000/qualifier-alerte?disable_ml=true
When to use each mode ML ON (default): Production and demos. Engine 1 silently drops obvious false positives before LLaMA 3 even wakes up.
ML OFF: Deep debugging. Forces every single alert through LLaMA 3 so you can read the full reasoning for each one.

🧠 The AI Memory (SQLite)

The SOC AI doesn't just look at alerts in isolation. It has a built-in memory system powered by a local SQLite database (soc_memory.db).

What is stored?

Every time an alert is processed, the system logs:

  • The Source IP
  • The Alert Description
  • The AI's Classification
  • The Attack Type
  • The Action Executed (if any)
  • The exact Timestamp

Why is this important?

1. ML Engine Velocity Tracking (Engine 1)
Engine 1 checks the SQLite database to calculate alerts_per_minute. If an IP suddenly spikes in activity (e.g., 50 requests in 60 seconds), the ML model sees this feature and is much more likely to flag it.
2. LLaMA 3 Historical Context (Engine 2)
Before LLaMA 3 makes a decision, it queries the database: "Has this IP attacked us in the last 24 hours?"
If the IP is a repeat offender, this context is injected into LLaMA's prompt. LLaMA uses this to escalate the threat level and become more aggressive in its recommendations, even if the individual alert seems minor.

🔧 Troubleshooting

ProblemCauseFix
Read timed out on first test LLaMA 3 wasn't pre-loaded in RAM The API warmup handles this automatically on startup. Just wait for the ✅ warmup message.
Connection refused API is not running Run uvicorn api:app --host 0.0.0.0 --port 8000 first.
engine2_llm: indisponible Ollama is not running Run ollama serve in a terminal.
engine1_ml: indisponible models/ folder is missing .pkl files Run python retrain_engine1.py to regenerate the models.
All tests return Suspect LLaMA 3 is being too conservative This was fixed in the latest update to soc_agent.py. Restart the API.
Scary message after Ctrl+C Intel Fortran runtime in Anaconda's numpy This is completely harmless. Ignore it.

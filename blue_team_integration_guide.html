🛡️ Active Defender SOC AI

Welcome! This guide is designed to be simple and straight to the point. Here is exactly how to connect to the AI and test it.

1. How the Dual-Engine Works

Engine 1 (Fast Filter): Analyzes the text and time of the alert. If it's 100% sure it's a False Positive, it drops it instantly (0.1s).
Engine 2 (LLaMA 3 Brain): If Engine 1 is unsure, or if Threat Intel flags the IP, this engine takes over. It reads the IP history, checks SOC playbooks (RAG), and makes a logical decision.

2. Connecting via n8n

Use an HTTP Request Node in n8n with these settings:

  • Method: POST
  • URL: http://100.64.X.X:8000/qualifier-alerte (Replace with the AI's Tailscale IP)

3. The JSON Formats

What you send to the AI:

{
  "alert": {
    "id": 1234,
    "description": "{{ $json.wazuh_description }}",
    "level": {{ $json.rule_level }},
    "src_ip": "{{ $json.src_ip }}",
    "timestamp": "{{ $json.timestamp }}"
  },
  "threat_intel": {
    "misp": { "found": {{ $json.misp_found }} },
    "opencti": { "found": {{ $json.opencti_found }} }
  }
}

What the AI replies with:

{
  "analysis_context": "L'alerte mentionne un SSH Brute Force. L'IP source est...",
  "reasoning": "L'attaque se produit en dehors des heures de travail...",
  "classification": "Critique",
  "automated_action": {
    "execute": true,
    "action_type": "firewall-drop",
    "target": "203.0.113.50"
  }
}

4. Testing & Debugging

To run the built-in tests, open a terminal on the AI machine and type:

python stress_test.py
💡 Pro Tip: Testing the ML Toggle
If you want to bypass Engine 1 completely and force LLaMA 3 to read every single alert, open stress_test.py and change USE_ML_ENGINE = True to False.

You can also do this in n8n by adding ?disable_ml=true to the end of the URL.
